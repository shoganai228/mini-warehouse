# Веб-приложение «Мини-склад» (BMS Smart Home)



Веб-система управления остатками товаров на складе, учета прихода/выдачи и истории операций с разграничением прав доступа.



## Технологический стек

* **Backend:** Python 3.12, Django 5.x

* **Database:** SQLite (Decimal-типы для точных расчетов)

* **Frontend:** Django Templates, Bootstrap 5 (адаптивная верстка под ПК и мобильные)



---



## Быстрый запуск (занимает до 5 минут)



1. **Клонируйте репозиторий / распакуйте архив с проектом:**

   cd clad



2. **Создайте и активируйте виртуальное окружение (при необходимости):**

   python -m venv .venv

   source .venv/bin/activate  # Для macOS/Linux

   # .venv\Scripts\activate   # Для Windows



3. **Установите зависимости:**

   pip install django



4. **Примените миграции базы данных:**

   python manage.py migrate



5. **Запустите локальный сервер:**

   python manage.py runserver



   Приложение будет доступно по адресу: http://127.0.0.1:8000/

## Тестовые учетные записи



В системе заранее подготовлены три роли со следующими данными для входа:



* **Руководитель** (`chisay_admin`): Полный доступ — управление остатками, приход/выдача, отмена операций, просмотр цен и истории.

* **Кладовщик** (`storekeeper1`): Приход и выдача товаров. Цены и финансовые итоги скрыты на уровне сервера.

* **Менеджер** (`manager1`): Только просмотр остатков и цен. Нет кнопок прихода/выдачи и доступа к истории.

> **Что сделано и какие решения приняты:**
> 1. **Архитектура и безопасность:** В качестве стека выбрана связка Python + Django. Интерфейс построен на сервере (Django Templates + Bootstrap 5) с поддержкой тёмной темы и адаптивности под мобильные устройства.
> 2. **Контроль прав на сервере:** Все ограничения ролей (Руководитель, Кладовщик, Менеджер) зафиксированы строго на бэкенде. Кладовщик не получает данные о ценах даже при прямых запросах в обход UI.
> 3. **Бизнес-логика остатков:** Реализована валидация отрицательных остатков. Отмена прихода блокируется, если товар из него уже выдан на объекты и операция приведет к минусовому балансу.
> 4. **Точность денег и надежность:** Все денежные поля используют `Decimal` (без ошибок округления плавающей точки). Итоги считаются отдельно по каждому типу валют. Добавлена защита от повторной отправки формы при двойном клике.
> 5. **Каталог товаров:** Управление справочником вынесено в административную панель Django.
